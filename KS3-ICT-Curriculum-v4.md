# KS3 Computing Curriculum (2026–2027) — v4

### ***Years 7–9 · Built on the Progress in Computing book (Hodder) · one book module per half-term***

**What changed in v4:** the curriculum now runs **one book module per half-term** across all three years, following *Progress in Computing*. **Coolest Projects is now an after-school club**, not the Year 9 capstone. **Year 9** opens with a **Raspberry Pi introduction** (own unit, not from the book), then the book's Algorithms and Python modules and Experience AI, and **pairs each module with a short systems & theory topic** to bridge into Year 10 GCSE Computer Science (Pearson Edexcel). AI is delivered through **Experience AI**; each year also has an **extension module** (Ext).

**Microsoft 365 routine:** **every year opens HT1 with a short induction — Computer lab & Microsoft 365 (accounts, Teams, OneDrive)** — so students can log in, collaborate and keep their work organised from day one, before the first module begins.

**Assessment principle:** **short quizzes** during units, and **at least one assessed piece of evidence every half-term**. All reported **Emerging → Developing → Secure → Notable → Mastery**.

**Types of assessment** *(what each piece of evidence is — named in each table):*

- **Quiz** — a short knowledge check during a unit.  
- **Written test** — an end-of-unit test of understanding.  
- **Presentation** — present work to the class (Canva or PowerPoint).  
- **Coding project** — a working program built in Scratch, MakeCode or Python.  
- **Practical project** — a created product (graphics, video, website, data analysis or a physical-computing build).

**Book module key:**

- **M1** — Getting started

## **YEAR 9 — Hardware, Algorithms, Python & AI**

*Year 9 is a **bridge to GCSE Computer Science** (Pearson Edexcel, Year 10): alongside the programming and algorithms modules, each half-term adds a paired **systems & theory topic** (both shown in the Module column), so the two strands mirror the GCSE's own programming-plus-theory structure. Each half-term is assessed on **both** strands — a coding or practical piece for the programming, plus a short **quiz or written test** on the systems & theory topic (GCSE-style). Light-touch by default (a few lessons per half-term) — push harder where time allows.*

| HT | Module | Focus | Assessment evidence |
| :---: | :---- | :---- | :---- |
| **1** | **Induction \+ The Raspberry Pi \+ Hardware & the CPU** | *Induction: Computer lab & Microsoft 365\.* Then the **Raspberry Pi** as an introduction to what a computer is (own unit, not from the book): parts, physical computing, hardware & software; then getting started — the desktop & OS, files, connecting peripherals, first hands-on use ([getting-started guide](https://www.raspberrypi.com/documentation/computers/getting-started.html)). **Systems & theory:** components, RAM/ROM and the **fetch–execute cycle** (supported by the School Computer Simulator). | **Practical project** — set up and use a Raspberry Pi (guided getting-started tasks)  **Quiz** — hardware, RAM/ROM & the fetch–execute cycle. *365 induction \= formative check.* |
| **2** | **M8 — Algorithms \+ Data representation 1** | Computational thinking to solve problems; pattern recognition; flow diagrams; Cholera in Soho; Malaria in Kitanga; Meet the Potato Heads. **Systems & theory:** binary ↔ denary, binary addition & overflow, hexadecimal (deepens Y7 binary). | **Written test** — computational thinking & algorithms (incl. a flow-diagram task) **and data representation** (binary, binary addition & overflow, hexadecimal). |
| **3** | **M6 — Python: sequence \+ Data representation 2** | Computer programs; getting data from the user; data types; placeholders & lists; working with lists; working with strings. **Systems & theory:** ASCII / character sets, bitmaps, sound & compression. | **Coding project** — a Python program using **sequence** (input, data types, lists, strings)  **Quiz** — data representation (ASCII, bitmaps, sound, compression). |
| **4** | **M9 — Python: selection \+ Storage & the OS** | Selection; decisions based on calculations; if/else; comparing strings & numbers; elif; multiple elifs. **Systems & theory:** primary vs secondary storage and media, plus file management. | **Coding project** — extend the program with **selection** (if / else / elif) **Quiz** — storage & the operating system. |
| **5** | **M15 — Python: iteration \+ Networks** | Repeating instructions; user-defined for loops; for loops with strings & lists; searching with for loops; while loops. **Systems & theory:** LAN/WAN, IP, protocols, TCP/IP & packet switching (deepens Y8 networking). | **Coding project** — extend the program with **iteration** (loops) **Written test** — networks (LAN/WAN, protocols, TCP/IP, packet switching). |
| **6** | **Experience AI \+ Issues & impact** *(Raspberry Pi Foundation)* | Deeper **artificial intelligence & machine learning** — models, large language models and AI ethics (builds on Y8). **Systems & theory:** privacy, data-protection law & cyber security (leads on from Experience AI toward GCSE Topic 5). | **Presentation** — an AI & machine-learning explainer **Written test** — issues & impact (privacy, data-protection law, cyber security). |
| **Ext** | **The School Computer Simulator** | A model of a computer as a **school building** — office \= CPU, instructions in the Primary Rooms (primary memory), data in the secondary rooms (secondary storage). Write & run **simple low-level programs** in the spreadsheet, and run it **unplugged** to act out the **fetch–execute cycle**. | *Optional* **Coding project** — write, run & explain a low-level program (early finishers / spare time). File: `TheSchoolComputer.xlsx`. |

## **Assessment Rubrics (by assessment type)**

*Each assessment **type** has its own rubric — 3–4 criteria, each judged across five levels (**Emerging → Developing → Secure → Notable → Mastery**). Find the assessment's **type** in the year tables (e.g. Presentation, Coding project) and use the matching rubric below.*

### **Written test / Quiz**

| Criteria | Emerging | Developing | Secure | Notable | Mastery |
| :---- | :---- | :---- | :---- | :---- | :---- |
| **Recall** (terms & facts) | Recalls a few terms with help | Recalls most key terms | Recalls key terms & facts accurately | Recalls accurately, with detail | Recalls thoroughly and precisely |
| **Understanding** (explains ideas) | Identifies ideas with help | Explains simple ideas | Explains key concepts correctly | Explains clearly, with examples | Explains and links concepts |
| **Application** (uses knowledge) | Answers basic questions with support | Answers familiar questions | Applies knowledge to set questions | Applies to less-familiar problems | Applies confidently to new problems |

### **Presentation**

| Criteria | Emerging | Developing | Secure | Notable | Mastery |
| :---- | :---- | :---- | :---- | :---- | :---- |
| **Content & research** | Few points; little research | Some relevant, researched points | Accurate, relevant, researched content | Well-researched, balanced content | Insightful, thoroughly researched |
| **Structure & clarity** | Disorganised; needs help | Some structure | Clear, logical structure | Well-sequenced, easy to follow | Compelling, purposeful structure |
| **Design & visuals** | Plain or cluttered slides | Basic, mostly clear slides | Clear, appropriate visuals | Polished, effective visuals | Professional, audience-tuned design |
| **Delivery** | Reads with prompting | Speaks with some confidence | Speaks clearly to the audience | Engages the audience; good pace | Confident & persuasive; handles questions |

### **Coding project**

| Criteria | Emerging | Developing | Secure | Notable | Mastery |
| :---- | :---- | :---- | :---- | :---- | :---- |
| **Functionality** | Runs only with help | Partly works | Works and meets the brief | Works well; extra features | Fully works; robust & ambitious |
| **Programming constructs** | Uses given code | Uses sequence & selection | Uses sequence, selection, iteration & variables | Uses them efficiently | Efficient, well-chosen (e.g. lists/functions) |
| **Design & decomposition** | No real plan | Some planning | Plans & decomposes the problem | Clear, structured solution | Elegant, well-structured & reusable |
| **Testing & debugging** | Spots obvious errors with help | Fixes simple bugs | Tests & debugs independently | Tests systematically | Rigorous testing; explains fixes |

### **Practical project *(graphics, video, website, data or a physical-computing build)***

| Criteria | Emerging | Developing | Secure | Notable | Mastery |
| :---- | :---- | :---- | :---- | :---- | :---- |
| **Planning & design** | Little planning | Basic plan/design | Clear plan & design | Thorough, considered design | Original, well-justified design |
| **Technical execution** | Uses tools with help | Uses core features | Uses the tools competently | Uses the tools skilfully | Fluent, advanced tool use |
| **Quality of outcome** | Incomplete/rough | Basic; fit for purpose | Complete & fit for purpose/audience | Polished & effective | Professional, creative & impactful |
| **Evaluation** | Says if they liked it | Basic comments | Evaluates against the brief | Evaluates & suggests improvements | Critically evaluates & iterates |
